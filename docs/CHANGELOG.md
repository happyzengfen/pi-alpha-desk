## 第三部分：v9 — 刷新链路重构完成（本轮全部改动）

### 1. PPT 刷新链路重构（解决"PowerPoint 保存后刷新仍是旧内容" + 5 秒更新目标）

| # | 改动 | 说明 |
| --- | --- | --- |
| 1.1 | **探测与转换合并** | 删除独立的 `detectPresentationCom`（每次刷新启动一次 PowerShell 探测，1-2s）→ 探测逻辑并入转换脚本内一次调用完成 |
| 1.2 | **路 B 内存直出** | GetActiveObject 复用运行中的 PowerPoint/WPS → 在 Presentations 中按完整路径/文件名匹配用户已打开的文档 → 直接 SaveAs 导出 PDF（只读导出：不 Close 用户文档、绝不 Quit 用户实例）；匹配失败才打开磁盘副本（路 A）——**PowerPoint 开着时也能拿到最新内容** |
| 1.3 | **单飞锁** | 同一文件并发请求（N 页并发加载）共享同一次转换，不再各自启动转换 |
| 1.4 | **mtime 毫秒精度** | 缓存判断去掉 `Math.floor`（同秒保存也能识别变化，消除"保存后仍旧"次因） |

### 2. PDF 渲染侧缓存（刷新提速）

| # | 改动 | 说明 |
| --- | --- | --- |
| 2.1 | **页面图缓存** | 按 PDF 路径 + mtimeMs + size 为键，页面 PNG 落盘缓存——文件未变零解析零渲染（实测 200ms → 5ms）；文件变化键自动更新 |
| 2.2 | **文档解析缓存** | 最近使用的 PDF 解析结果 30 秒内复用，消除 N 页请求各自重复解析（每页省 0.5-1s） |

**实测**：PowerPoint 打开文件 → 修改保存 → 软件内刷新拿到新内容 ✓（用户验证通过）

### 3. 文件变更指示（独立增量，可整体移除）

| # | 改动 | 说明 |
| --- | --- | --- |

| 3.2 | **前端 hook** | `hooks/use-file-change-indicator.ts`：每 **3 秒**轮询一次 stat → 与基准对比 → 变化则变色提醒；点击刷新/切换文件自动重置基准 |
| 3.3 | **刷新按钮变色** | 检测到更新 → 刷新按钮变 accent 色（与"适应宽度"选中同款，无圆点无文字）；点击刷新后恢复背景色 |

| # | 改动 | 说明 |
| --- | --- | --- |
| 4.1 | **当前页判定改面积最大** | 参考线（顶部 24px）→ 视口内**可见面积最大**的页；**严格大于**比较 → 面积相同保留页码更小者（优先上方页）；固定页高下为纯计算（不依赖图片加载）——修复"看第 3 页时第 2 页露底边误判为 2" |

# v10 — PPT 转换脚本修复 + PATH 大小写修复（2026-08-18）

## 修复 1：转换脚本反斜杠编译丢失

- **现象**：PPT 预览"提示有更新但刷新后内容不更新"（安装版）
- **根因**：源码 `-replace "/", "\\"` 经编译后反斜杠丢失变成 `-replace "/", ""` → PowerShell 5.1 解析异常（参数绑定失败）→ 转换必失败 → 静默返回旧缓存
- **修复**：`lib/pptx-convert-tool.ts` 改用 `[string][char]92`（数字编码，对编译环境免疫）

## 修复 2：electron 服务 PATH 大小写 bug

- **现象**：修复 1 后安装版转换仍失败（501，快速失败）
- **根因**：electron 环境变量 key 是 `Path`；`{...process.env}` 展开成普通对象后 `env.PATH` 为 undefined → 服务进程 PATH 被截断为只剩 node 目录 → `spawn powershell.exe` ENOENT
- **修复**：`electron/node-runtime.js` 的 `prependExecutableDirectory` 大小写不敏感查找 PATH key
