# 桌面自动化使用说明

自动化把事件、定时任务、Pi 执行和待决定事项连接起来。它默认关闭；普通聊天继续沿用原有模型、工具和 pi-goal 设置。

## 开始使用

1. 启动 Electron 应用，打开设置中的“自动化”，启用桌面自动化。
2. 新建规则，选择工作目录，填写目标和触发方式。新规则默认停用，可先保存检查。
3. 选择手动、cron 周期或一次性预约；周期任务使用页面上明确显示的时区。
4. 按需指定模型、思考等级、单轮超时和每日启动轮数上限，然后启用规则。
5. 手动规则点击“立即运行”。任务提出问题后，在“待决定”中选择或填写回答；后续执行接着原会话。

标题栏显示待决定数量。历史页可查看触发原因、回执和回答，并打开对应 Pi 会话。卡片保存在本机数据库，刷新、切换会话或重开应用后仍存在。

首版自动化只启用 `read / grep / find / ls`，不加载用户、项目或内置续跑/交互扩展，也不启用 shell、写入、编辑和子 Agent。这限制的是工具能力，不是操作系统文件沙箱；读取工具可能读取工作目录之外的文件。模型必须在已配置的可见范围内；依赖扩展注册的模型提供商不在此模式加载。

隐藏到托盘后继续工作；菜单“退出”停止领取并有界清理自有进程。休眠或完全退出期间不会执行；恢复后合并错过的周期触发，不逐个补跑错过的时间点。

系统通知不可用时，仍可从标题栏进入“待决定”回答卡片。原生后台问答、退出重开与性能已经实测；通知投递/点击、托盘恢复和标题栏拖动仍未完成发布验收，当前结果见[验证报告](automation-validation.zh-CN.md)。

## 等待、取消与结果不明

- 等待决定不持续调用模型。回答后是新的一轮，保留原 Pi 会话。
- 缺少认证或提供商明确拒绝认证/访问时，会留下恢复问题。等待期间，后续手动事件和周期触发保留在队列中，不再次请求该模型；其他任务仍可执行。修复认证后选择继续，或选择暂停此任务。
- 延迟复查由持久预约唤醒，不依赖打开的页面。
- 停用规则/取消任务会阻止后续触发，并使旧执行的迟到回执不能新建问题、预约和工作。
- 关闭整个自动化会先中止并等待当前执行清理。若无法确认停止，保留待处理状态，不能假定副作用已经撤销。
- “结果不明”表示上次业务可能已经开始。先查看历史与会话，确认旧执行已停止，并检查会话内容、已完成步骤及文件缺失/损坏情况，再点击明确的复核按钮。崩溃后会话可能含已写入的 SDK 内容，采纳这些内容继续需要此次显式复核；不能只凭租约到期重跑业务。
- 若业务已完成，但回执修复未能确认停止，核实后只记录原业务结论、用量和复核通知；该次回执的问题、预约与派生工作不会生效，也不会重新执行业务。
- 无法从提供商取得可靠认证状态时，通用错误会进入待核实，不猜测其原因或自动重试已开始的工作。
- 失败有有限退避重试；达到每日启动上限会停用规则并留下通知。已完成业务不会因回执修复失败而重做。
- 纯定时复查连续三轮给出相同结论及相同后续复查内容，会停用规则并生成一张复核通知。复查时间戳不参与比较；新事件、人工回答、内容变化或重新启用会重置计数。这是明确的重复回执保护，不是对任意业务进展的语义判断。

## 会话查看与修改

打开自动化会话查看历史不会切换它的模型；执行时仍核对当前可用模型范围。回执修复使用同一会话的无工具执行，重新加载资源也不会重新启用工具。

重命名或删除自动化会话前，应用会先停用关联任务并等待执行退出。无法连接自动化宿主、完整确认关联任务或核实旧执行时，操作会被拒绝，文件保持原样；普通会话继续使用原有操作方式。

直接修改、截断、删除或损坏会话文件，会让关联任务暂停。应用不会让 SDK 先覆盖损坏文件，也不会把变动后的历史自动认作原任务。此类人工变更造成的暂停记录不会被普通“确认停止”清除；核对已完成工作后，可新建规则使用新的专用会话。暂停原因和后续操作可在已处理通知中查看。

## 模型回执

执行器会提供协议说明和单独的资料文件。普通完成只需最后一条文字结论；需要提问或复查时，在最后一条回复中附加 `agent-autoloop` JSON 块。例如：

````text
已核对巡检资料，需要你决定下一步。
```agent-autoloop
{
  "ask": [{
    "title": "接下来检查哪项？",
    "text": "已有资料核对完成，请选择下一项。",
    "options": ["日志", "配置"],
    "key": "next-check",
    "about": "回答后只检查选中项目，不重做已完成的核对。"
  }]
}
```
````

还支持 `notice`、`resolve`、`later`、`events`。派生事件类型须经规则允许；重复事件与回执会去重。卡片同 key 对未解决问题去重，预约同 key 更新或取消。

## 运行时与本地开发

普通应用的 Node 下限保持不变。hub 单独要求 Node 24 和可用的 `node:sqlite`；桌面探测匹配平台/架构的独立 Node 与 Electron 内置 Node。能力不足只让自动化不可用，普通聊天仍可启动。

开发与打包命令会生成 `dist/automation-hub/`：

```sh
npm run automation:build
npm run electron:dev
```

桌面开发模式若连接已有外部 Next 服务，不会接管其自动化。需要桌面启停时，先关闭外部服务，让 Electron 启动自己的服务。

纯浏览器开发可显式启动 hub，再在另一终端把同一 descriptor 路径传给 Next：

```sh
# 使用绝对私有目录，不与 ~/.agent-autoloop 共用。
npm run automation:host -- --data-dir /absolute/private/pi-automation --descriptor /absolute/private/pi-automation/connection.json

# 另一终端。descriptor 有服务端凭据，不要上传或提交 Git。
PI_AUTOMATION_DESCRIPTOR=/absolute/private/pi-automation/connection.json npm run dev
```

两进程需同时运行。浏览器模式不提供 Electron 原生通知或宿主启停按钮，规则、收件箱和历史仍通过相同 API 使用。

## 验证

```sh
npm test
npm run test:automation
npm run typecheck:automation
./node_modules/.bin/tsc --noEmit
npm run lint
node scripts/verify-automation-package.mjs --dir . --probe
node scripts/verify-automation-package.mjs --dir . --probe --electron
```

专项测试使用临时目录、本地假模型及真实 SQLite/HTTP/Pi SDK，不调用付费模型。跨平台 CI 位于 `.github/workflows/automation.yml`；配置 CI 不代表平台已经实测通过，结果以对应 runner 为准。

## 数据、备份与升级

数据位于 Electron 用户数据目录的 `automation/`，与 Pi JSONL 分开，包括 `hub.db`、`master.key`、规则与宿主偏好、worker 检查点/outbox、会话绑定和本次连接 descriptor。

备份前完全退出，确认自有 hub/Next 已结束，再复制整个 `automation/` 目录并备份 Pi 会话目录。不要只复制运行中的主 db 而遗漏 WAL，也不要丢失 master key 或待交回执。恢复时保持原权限，并核对项目及会话路径；重启会生成新连接凭据。

升级前保留旧版本与完整备份。投影格式变化从事实日志重建，不改旧事实；新数据不保证可直接交给旧版本写入。回滚先停用自动化，再恢复经过核验的完整备份。结果不明的任务仍需核实。

外部业务来源/通知通道、自动编辑/发布、系统常驻服务和 pi-goal managed-run 属于后续扩展。见 [集成计划](agent-autoloop-integration-plan.zh-CN.md) 和 [执行记录](../tasks/agent-autoloop.md)。
