# 文件查看与读取工具排查记录

日期：2026-10-03

本次检查已有的文件预览、聊天文件读取工具，以及桌面安装包中的相关资源。修复位于源码；当前运行的安装版尚未重新打包更新。

| 功能 | 确认的问题 | 修复后的行为 |
| --- | --- | --- |
| PDF 打开 | 文本读取加载 PDF.js 6 的 Worker，预览使用 PDF.js 4，先读后预览出现 HTTP 500 | 读取与预览统一使用同一引擎；初始化顺序和并发访问有回归测试 |
| PDF 文字 | 缺少标准字体路径，英文数字可能显示为空白；中文 CMap 使用不兼容的 file URL，文字可能被读成空 | 使用安装包内的标准字体与 CMap 文件路径；验证可见文字像素和中文提取 |
| PDF 分页、缩放 | 不同页面共用尺寸元数据；缓存未区分渲染比例；查看器套用第一页长宽比 | 每页独立保存尺寸，缓存区分比例；页面按真实尺寸排版 |
| PDF 读取工具 | 请求少量页面仍解析全文；解析对象未释放 | 只提取请求的页面；成功、越界和解析失败均释放资源 |
| PDF 兼容性 | 32 位 Windows 没有 Canvas 原生预编译组件；顶层导入可能使整个文件接口无法加载 | 延迟加载渲染组件，缺失时返回 501 并切换内置 PDF 查看器；其他文件接口继续可用 |
| PDF 错误提示 | 只显示 HTTP 状态；后续页面加载失败没有提示 | 显示服务端原因；失败页给出重试提示，其余页面继续阅读 |
| PPT | 缺少 Office/WPS 时没有启用已有大纲预览；大纲按文件名排序，XML 实体显示错误 | 自动使用大纲预览；按演示文稿实际顺序读取，正确还原并转义文字 |
| Excel、CSV、TSV | Excel 导出的 UTF-16 文件出现乱码 | 识别 UTF-8、UTF-16 LE/BE BOM，TSV 使用制表符解析 |
| 图片、源码 | 一次加载失败后错误状态阻止恢复 | 文件更新或成功重读后清除旧错误 |
| Word、表格备用预览 | 接口失败时 iframe 直接显示 JSON；刷新没有清除旧错误 | 显示可读错误，刷新可重新加载 |
| Word、PPT 导出 | 失败导出可能覆盖旧缓存；同名文件误匹配；PPT SaveAs 可能改变用户打开的文件 | 成功导出后才替换缓存；只按完整路径匹配；用户已打开的文档仅使用 ExportAsFixedFormat |
| 安装包验证 | 未检查 PDF Worker、中文 CMap、标准字体、Office 解析包和 Windows Canvas 架构 | 三个平台检查预览资源；Windows x64/arm64 检查原生组件架构，ia32 使用备用预览 |

验证包括普通与中文 PDF、不同页面尺寸、缩放缓存、先读取再预览、反向顺序、并发访问、故意缺失 Canvas 的文件 API、PPT 顺序与文字实体、CSV 编码、界面错误恢复及安装包资源。

在 Electron 43 的实际窗口中，保留现有 sandbox、contextIsolation、nodeIntegration 和 CSP 设置，确认内置 PDF 查看器能显示文字和页面内容。未放宽窗口或网络安全配置。

通过独立 Next.js 开发服务的实际 HTTP 请求，复核 PDF 页面图片、Word/PPT 转换器不可用时的 501 响应及 HTML 备用预览、UTF-16 表格预览。没有执行生产构建，也未替换正在运行的安装版。

音频文件的 MIME 与 Range 读取通过检查；已有源码、Markdown、图片和表格相关测试继续通过。本次没有新增独立视频预览。

Windows Office/WPS COM 导出需要 Windows 实机复核；macOS 上只能验证转换脚本和模拟执行路径。备用 Word/PPT 预览保留内容阅读能力，不保证与 Office 原始版式完全一致。
